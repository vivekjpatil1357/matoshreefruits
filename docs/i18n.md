# i18n — trilingual site (hi / mr / en)

The public site ships in three locales. **Hindi (`hi`) is the default**;
Marathi and English are full alternatives.

| Code | Display name | Notes |
| --- | --- | --- |
| `hi` | हिन्दी | `DEFAULT_LOCALE` — `/` redirects here for first-time visitors |
| `mr` | मराठी | — |
| `en` | English | Also the model default for data fields |

All configuration lives in [`../src/lib/i18n.js`](../src/lib/i18n.js):
`LOCALES`, `DEFAULT_LOCALE`, `LOCALE_NAMES`, `isValidLocale()`,
`getMessages()`.

## Routing

- Public pages live under the dynamic segment
  [`../src/app/[locale]`](../src/app/[locale]) (home, `stock`, `gallery`,
  `contact`, `feedback`). `generateStaticParams()` pre-renders all three
  locales; an unknown locale renders the 404 (`notFound()` in the layout).
- [`../src/proxy.js`](../src/proxy.js) (Next.js 16's middleware successor)
  handles `"/"`: it redirects to the `NEXT_LOCALE` cookie value when it is a
  valid locale, otherwise to `DEFAULT_LOCALE` (`/hi`). Its matcher is only
  `["/", "/admin/:path*"]` — locale URLs themselves need no rewrite.
- `<html lang={locale}>` is set per locale in the
  [layout](../src/app/[locale]/layout.js), which also supplies `meta.title`
  (with a `%s | …` template) and `meta.description` from the messages.

## Messages

Each locale has a complete translation dictionary in
[`../src/messages/`](../src/messages) (`mr.json`, `hi.json`, `en.json`),
loaded by `getMessages()` and passed to pages from the `[locale]` layout.
Top-level sections: `meta`, `nav`, `common`, `bar`, `hero`, `home`, `stock`,
`gallery`, `contact`, `feedback`, `footer`, `whatsapp`. Components never
hardcode user-facing copy — add keys to all three files together.

## Language switcher

[`LanguageSwitcher.js`](../src/app/[locale]/components/LanguageSwitcher.js)
is a client component: it writes `NEXT_LOCALE=<code>; path=/; max-age=31536000;
samesite=lax` and `router.push()`es to the same path under the new locale, so
the visitor stays on the page they were reading. The cookie is what the proxy
reads on the next visit to `/`.

## Localized data

Content documents store the English value plus Marathi/Hindi variants:

- Posts: `title`/`titleMr`/`titleHi`, `body`/`bodyMr`/`bodyHi`
- Stock: `variety`/`varietyMr`/`varietyHi`, `notes`/`notesMr`/`notesHi`

[`../src/lib/localize.js`](../src/lib/localize.js) resolves them:

- `localizedField(item, locale, key)` — returns `keyMr` for `mr`, `keyHi` for
  `hi`, else the base value (empty variant falls back to English).
- `formatDate(iso, locale)` — `Intl.DateTimeFormat` with `mr-IN` / `hi-IN` /
  `en-IN` tags.

Admins can fill the `Mr`/`Hi` variants in one click via **Auto-translate**
(`POST /api/admin/translate` — see [api.md](api.md) and
[admin-dashboard.md](admin-dashboard.md)).

The admin panel itself is English-only (one internal user) — see
[admin-dashboard.md](admin-dashboard.md).
